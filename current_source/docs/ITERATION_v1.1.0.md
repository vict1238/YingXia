# v1.1.0 工程说明

主线仍为 Go 后台 + 已安装浏览器应用窗口，版本 `1.1.0-exe`。未加入超分，也未迁移到 LibreTV 的 Next.js 或 Kazumi 的 Flutter 技术栈。

## 主要文件

| 文件 | 职责 |
|---|---|
| providers.json | 内置 17 个来源与固定上游快照 |
| providers.go | 来源注册、用户开关、自定义 CMS、并行搜索、来源专属影片 ID、配置备份 |
| rules.go | Kazumi API 1–8 的 XPath / JSONPath 规则，GET / POST、表单 / JSON、搜索与多组选集 |

## 来源身份与匹配

影片 ID 使用 `vod:<来源ID>:<Base64原ID>` 或 `rule:<来源ID>:<Base64原引用>`，解决不同 CMS 使用相同数字编号的问题。旧数字目录 ID 继续支持。收藏记录保存来源信息，重启后按同一来源重建详情。

同名候选保留为各来源的独立结果，不跨来源自动合并年份、季数或集数。换线仍按集名/自然集数匹配，缺少对应集时停止。每个来源的失败单独记录。

## 更新事务

1. 检查固定仓库的 main 提交，要求 40 位 SHA。
2. 从该 SHA 获取配置，避免索引和规则混用不同版本。
3. 验证公开 URL、规则 API、XPath / JSONPath 和请求结构。
4. 保留自定义来源；来源和解析开关从独立用户设置读取。
5. 原子替换 `source_registry.json`，只把有效旧文件保存为 `.previous`。

三个上游分别处理，一个失败不会阻止其他有效组件。不能理解的规则或脚本格式保留旧数据，并设置升级信号。仅监测 Kazumi 程序版本及 API，不下载运行其程序。没有 EXE 自更新。

## 播放

CMS 默认内置播放，仍可选择网页播放器。动漫优先尝试页面中的 video/source、MacCMS 普通 URL 编码或 Base64 字段；其次运行临时独立浏览器观察媒体请求；取不到时返回原播放页。

中转只接受后台已经登记的短期票据，不接受任意 URL 参数。主清单、子清单、分片、KEY/MAP 等 URI 均重新解析、校验并发放票据；用户关闭联网后接口拒绝媒体请求。规则 API 的公开 Authorization / apikey 不传到媒体 CDN。媒体中转不提供保存视频功能。

前端通过视频解码帧和时间推进记录“已播放”，iframe load 继续只记“播放页已打开”。合成测试和外部实播证据分开保存。

## 已知后续工作

当前重点是来源覆盖和数据更新。真实样本仍有站点验证、详情不匹配和媒体解码失败，详见 VALIDATION.md。后续可按具体来源逐个改善取流和失败后的播放体验；不要据搜索成功把全部来源标为可播。

本版支持自定义 CMS 单条/JSON 批量导入，尚未做任意第三方订阅 URL 的周期同步、TVBox 规则或直播源导入。

# v1.2.0 工程说明

主线仍为 Go 后台 + 已安装浏览器应用窗口，版本 `1.2.0-exe`。本版集中解决搜索结果需要反复试源的问题，保留 17 个内置来源、7 条解析线路、来源自动更新和极简界面，未加入超分或新第三方依赖。

## 搜索过程

1. 并行搜索启用的来源，逐步更新已完成的来源数；汇总候选后开始检查。
2. 对每条候选检查详情和可用分组，再检查对应播放入口。
3. 直接媒体检查有限响应样本；HLS 检查清单和有限分片样本。网页入口单独记录页面可访问。
4. 按检查结果排序，媒体可访问优先，其次页面可访问，失败和未完成结果靠后；同级仍保留片名、年份和季数的原有匹配顺序。
5. 打开候选时优先选择本轮检测成功的分组，原有集数匹配和缺集保护继续生效。

结果保留来源专属影片 ID，不跨来源自动合并同名作品，也不因同来源的一部片失败把其他影片全部判为失败。搜索页显示来源搜索和候选检查进度，用户可取消进行中的任务。

## 检查边界

`media_ok` 表示所检查媒体样本可访问，显示“媒体可访问”；`page_ok` 表示所检查播放页可访问，显示“页面可访问”。实际播放仍由内置播放器的解码帧及时间推进单独记录。网页可访问不当作媒体解码成功。

所有检查沿用公网 URL、DNS、TLS、会话和联网开关限制，不通过关闭安全校验来提高通过率。媒体只读取有上限的样本，不下载整部影片。

## 任务与缓存

检查并发上限 6，搜索任务总时限 150 秒；成功缓存 3 分钟，失败缓存 45 秒。缓存按候选和有效来源配置区分，避免旧配置检查结果继续影响新规则。取消或新搜索使旧任务失效，旧请求迟到不能覆盖当前搜索结果。任务结束后释放上下文与资源。

## 接口与相关文件

- `POST /api/search/start`：启动异步搜索。
- `GET /api/search/status?id=…`：读取来源进度、候选和访问检查状态。
- `POST /api/search/cancel`，请求体 `{"id":"…"}`：取消任务。
- 旧 `POST /api/search` 保留同步兼容入口，搜索页使用新接口。

| 文件 | 职责 |
|---|---|
| search_jobs.go | 搜索任务、进度、取消及结果汇总 |
| availability.go | 候选详情、播放入口及媒体样本检查、缓存和排序 |
| providers.go、service.go、server.go | 来源候选、搜索任务和本机接口的衔接 |
| media.go、network.go | 有界媒体读取及原有网络安全边界 |
| web/app.js、web/index.html、web/app.css | 进度、访问状态、排序结果与取消交互 |
| search_jobs_test.go、availability_test.go | 异步任务及候选访问检查回归 |
| docs/search_filter_smoke.cjs | 搜索检查界面的专门回归 |
| docs/browser_smoke.cjs | 原有播放、来源设置、收藏等整体回归 |
| docs/release_smoke.cjs | 最终 Windows EXE 进程及内嵌资源检查 |

搜索进度使用 `#search-progress`、`#search-progress-bar`、`#search-progress-label` 和 `#search-cancel`。候选可能在检查完成前显示，回归须等待任务结束再验证最终顺序或打开影片。

来源协议与更新事务沿用 `ITERATION_v1.1.0.md`。本轮证据集中在 `validation_v1.2.0/`，旧版记录保持原日期，不能作为当前来源可用性证明。

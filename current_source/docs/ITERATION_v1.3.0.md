# 映匣 v1.3.0

本次把主界面从 Edge/Chrome 应用模式迁移到映匣自己的 Windows 窗口。沿用已确认的极简页面、Go 本机服务、影视源、搜索筛选和本地数据，不加入超分；Android 版本不在本次交付范围。

## 窗口与运行时

- Go 程序创建 Win32 窗口，WebView2 在窗口内显示现有 HTML/CSS/JavaScript，主界面不再启动浏览器 `--app` 窗口。
- 采用 `github.com/wailsapp/go-webview2 v1.0.23` 的纯 Go 加载路径，构建无需 CGo/C++ 工具链；本工程不使用 Wails 框架。
- WebView2 使用 Microsoft WebView2 Runtime。EXE 未捆绑完整运行时；缺少时提示微软安装地址。WebView2 的进程与映匣窗口属于正常的内嵌网页运行结构。
- 主界面使用独立的 WebView2 配置，不读取日常浏览器账号。旧版 `browser-profile` 保留，但不再作为新主窗口配置使用。
- 关闭主窗口结束本机后台；重复启动唤起已有实例。开发参数 `--no-browser` 仍支持只运行本机服务。

## 播放与界面

原搜索、播放工作台、收藏与记录、来源与诊断保持。切出工作台自动暂停，返回后手动继续；原空状态提示及右上角入口精简保留。

主窗口最小化时暂停播放。内置视频暂停并保留位置；网页播放器移除 iframe 结束播放，恢复窗口后手动打开。全屏同步 WebView2 与 Windows 窗口，隐藏标题栏并覆盖所在显示器，退出恢复窗口尺寸和样式；本轮发布 EXE 已实际验证。

动态取流仍保留现有策略：静态解析未取得媒体地址时，部分来源使用已安装 Edge/Chrome 的临时无头实例。该解析步骤与主界面容器分开，任务结束后清理临时配置。移除主界面对桌面浏览器窗口的依赖，不等于所有动态取流都不再使用桌面浏览器。

## 数据与兼容

默认数据目录继续为 `%LOCALAPPDATA%\YingXia\standalone`，现有 `library.json`、`source_registry.json`、来源开关、收藏与历史沿用。上游来源更新仍为配置更新，不替换本地 EXE。

本机服务继续只监听回环地址；会话、CSRF、Host/Origin、公共 URL/DNS 校验和媒体接力边界保留。换窗口不更改第三方片源状态，也不把页面加载或媒体样本访问升级为完整播放验证。

新增宿主导航、弹窗和下载策略使用本工程的最小 COM 声明，避免依赖生成包的初始化回调与继承 ABI 问题；不修改 vendor。调试端口只在显式设置 `YINGXIA_WEBVIEW_DEBUG_PORT` 时启用，普通启动不开放调试监听。

## 构建与验证

版本为 `1.3.0-exe`，对外交付 `YingXia_v1.3.0_Windows_x64.exe` 与同名源码 ZIP。依赖通过 `vendor/` 固定，构建命令见 README 与 `BUILD_INFO.json`。

v1.2.1 的 README、验证、构建信息、第三方说明和打包脚本在更新前保存至 `history_v1.2.1/`。本轮 Go、浏览器、发布 EXE 后台和原生窗口检查通过；具体数量、范围与限制见 `VALIDATION.md`，原始证据放在 `validation_v1.3.0/`。发布包保留源码、依赖许可、构建和测试记录，按清单验证 ZIP 内文件哈希。

# v1.2.0 验证记录

日期：2026-10-14；Windows x64，Go 1.27.2 windows/amd64。原始记录位于 `validation_v1.2.0/`。

## 本轮结果

- Go 离线 vendor 回归：191 条 PASS 记录，含顶层与子用例；2 个手动入口跳过。使用 `go test -mod=vendor -c -o build/yingxia_testserver.exe .` 编译，再执行工作区测试程序 `-test.v`。临时目录中的测试执行曾被 Windows Application Control 拦截，未修改系统策略；工作区正常构建和执行成功。CGO_ENABLED=0，未运行 race detector。
- `go vet -mod=vendor ./...` 和 JavaScript 语法检查通过。
- 搜索专项 Chrome 回归：10 项通过，覆盖真实计数进度、检测前禁点、正常与失败排序、备用分组选择、取消、迟到状态不覆盖新结果、迟到 start 请求串行化、会话与 CSRF、390–1340 宽度和零外联。
- 原有 Chrome UI 回归：17 项通过，含合成 WebM/HLS 实际解码、时间推进、画质/倍速、自动下一集、停止竞态、收藏/历史、来源管理和更新状态。
- 最终 Windows EXE 回归：8 项通过，覆盖内嵌来源与 HLS 库、中文/空格数据目录、会话、演示排除、单实例、界面、退出及收藏重启保存。`release_tests.json` 记录对应 EXE 哈希。

## 实际外联检查

对最终 EXE 使用独立临时目录，查询“葬送的芙莉莲”，启用全部 17 个来源。搜索与访问检查共约 38 秒：27 条候选全部检查，其中 1 条 `media_ok`、21 条 `page_ok`、5 条 `failed`，没有 pending 或未检测结果。排序断言通过，媒体样本正常的结果在前，失败结果在后。

无损云第二季候选的媒体样本通过；同来源第一季候选未取得匹配详情而后置。7sefun 两条候选的播放入口未返回有效页面/媒体，MXdm 两条候选返回 403，也被后置。说明同一来源的每部影片分别检测，不把一次成功或失败套用于该来源的所有作品。

详见 `live_search_filter.json`。此检查读取有限媒体样本，未验证真实影片完整解码或全片播放；21 条页面成功只表示对应播放页可访问。上述状态不永久禁用来源。

## 检查与并发

正常候选检查最多并发 6 个，单候选上限 22 秒，媒体样本单次最多 192 KiB；HLS 检查清单、初始化/密钥（如适用）和首个分片。总任务上限 150 秒，检查阶段上限 110 秒。成功缓存 3 分钟，失败缓存 45 秒；取消、总预算用尽或联网关闭不写失败缓存。

测试覆盖：HTTP 200 的 HTML 冒充媒体、挑战/空页面、HLS 主/子清单、分片/初始化、标准 AES-128 identity-key 样本、字节范围、非公网子 URL、失败备用线路、正常首集、缓存过期及配置变化、旧规则详情回写竞态、后续 MAP 不影响首分片、取消和关闭联网、过期任务、不可变进度快照、Web 页面模式。

完整 vendor 依赖可离线构建。第二次构建与发布 EXE 逐字节相同，PE32+ / x86-64 / Windows GUI；见 `build_reproducibility.json` 和 `BUILD_INFO.json`。v1.0、v1.0.2、v1.1.0 发布 EXE 保留且哈希未变。

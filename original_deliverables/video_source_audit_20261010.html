需要优先处理的五类问题：英文片名在空格处被截断；季数被删除；部分 B站 ep 标识被误当成自然集数；中文数字集数不识别；多个 $$$ 片源组只保留第一组。后者属于多源回退能力缺失，不是“已证明备用源能播”。

B站官方页面明确将 /bangumi/play/ep15014 标为第 1 集，而源码函数返回 15014。五位以内的标识可能触发该问题；六位及以上标识不会被这条正则直接当作集数，可能转用标题兜底，因此不能泛化为所有 B站页面都错。

4. 独立软件还缺什么

源码的无损云模块具有目录搜索；其余 7 条线路只接收已有的平台播放页 URL。它没有现成的“输入片名 → 获取各平台作品 → 匹配同一版本”的统一目录。因此桌面版需要独立维护作品元数据、平台链接和实际播放来源，不能把第三方源名称冒充官方平台。

匹配需要保留完整标题、年份、季数、正片/预告/剧场版和语言版本；平台内部标识与自然集数分开存储；多候选不盲选，缺集不自动跳第一集。多片源应保留完整分组，实际失败后再切换。

5. v1.0 的最低放行条件

至少一个真实来源完成可重复的“搜索 → 选对作品 → 选集 → 浏览器有解码画面且时间推进 → 换集”链路。随后补测同名片、不同年份、不同季、无结果、缺集及线路错误；自动回退只在实际错误信号后触发。Windows 内嵌播放器还需要目标环境测试，Linux 下的函数测试不能替代 Windows 播放验收。

本次交付的是预检工具和原始结果，不将其包装为已经能看片的 v1.0。目录或播放器页面可读取也不能验证影片授权、全部平台兼容性、4K/HDR、全剧可用性或长期稳定性。

6. 本机复测工具

source_check.py 使用 Python 标准库，支持搜索词、最多 3 个候选的详情和可选平台播放页转交测试；run_check.bat 用于 Windows 启动。需要 Python 3.10+，不需要额外 pip 依赖。它只核对网络和目录，始终保留 playback_verified: false，不会执行远程脚本或解码视频。

新的 Python 预检工具已完成语法检查、10 个离线单元测试和本环境网络错误处理测试。没有宣称在 Windows 上运行过。本机复测产生的报告可能含用户主动输入的网址，分享前需去除私人参数。
